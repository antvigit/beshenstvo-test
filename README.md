# Beshenstvo Test — автотесты для калькулятора прививок

Автотесты для сайта [beshenstvo.pro](https://beshenstvo.pro/) — проверка корректности отображения дат вакцинации.

---

## 🚀 Стек технологий

| Компонент | Технологии |
|-----------|------------|
| **Языки** | Java 11, Python 3.9+ |
| **Сборка** | Maven |
| **Тесты** | Selenium 4, JUnit 5 |
| **Отчёты** | Allure |
| **Архитектура** | Page Object Model + Page Factory, SOLID |
| **Логирование** | Log4j |
| **Контейнеризация окружения** | Docker Compose + Selenium Grid (Chrome + Firefox) |
| **Бот** | TeleBot, Flask, Requests (polling + health check) |
| **CI/CD** | GitHub Actions (матрица браузеров) |
| **Хостинг** | Render |

---

## 🧱 Архитектура проекта: ООП, POM, SOLID

Проект построен на принципах ООП, Page Object Model и SOLID:

- **ООП:** наследование (`VaccinationPage` расширяет `BasePage`), инкапсуляция, полиморфизм.
- **POM + Page Factory:** каждая страница — отдельный класс, элементы инициализируются через `@FindBy`.
- **SOLID:** Single Responsibility, Open/Closed, Liskov Substitution, Interface Segregation, Dependency Inversion.

---

## 🐳 Docker и Selenium Grid

Для запуска тестов в контейнерах используется **Docker Compose**, который поднимает Selenium Hub и узлы для Chrome и Firefox.

```bash
docker compose up -d
```
Тесты подключаются к Grid через переменные browser и grid.url.

## 🧪 Тесты

Автотесты покрывают основные разделы сайта: калькулятор вакцинации и калькуляторы
ревматолога (UI + backend API вакцинации).

### `VaccinationCalculatorTest` — калькулятор прививок (beshenstvo.pro)
- `shouldValidateVaccinationDates` — календарь вакцинации: наличие дат, формат `ДД.ММ.ГГГГ, День`,
  хронологический порядок и интервалы (3, 4, 7, 16, 60 дней)
- `testFullFormSubmission` — заполнение всей формы (ФИО, даты, серия, доза) и проверка
  генерации PDF (открытие новой вкладки с `blob:`-ссылкой)
- `shouldShowRepresentativeFieldsWhenCheckboxEnabled` — появление полей «ФИО представителя»
  и «Дата рождения представителя» при включении чекбокса «Указать законного представителя»
- `shouldGeneratePdfWithOnlyRequiredDateFields` — план формируется и при пустых ФИО/дате
  рождения, поскольку звёздочкой (`*`) на форме помечены только даты обращения и начала вакцинации
- `shouldToggleDarkTheme` — переключение тёмной/светлой темы (цвет фона, подпись кнопки)
- `shouldKeepVaccinationIntervalsForCustomStartDate` — интервалы 6 доз (0/3/7/14/30/90 дней)
  пересчитываются корректно при произвольной дате начала вакцинации

### `RheumatologyCalculatorTest` — калькуляторы ревматолога (beshenstvo.pro/rheumatology)
- Формулы `DAS28-ESR`, `DAS28-CRP`, `CDAI`, `SDAI`, `BASDAI` проверяются точным расчётом
  ожидаемого значения по опубликованным клиническим формулам и сравнением с результатом сайта
- Переключение шкал ревматоидного артрита (DAS28/CDAI/SDAI) и болезни Бехтерева
  (BASDAI/ASDAS-ESR/ASDAS-CRP/BASFI/BASMI) с проверкой набора полей на форме
- `SLEDAI-2K`: накопление баллов при отметке отдельных признаков и по категориям, сброс при
  снятии отметки, переключение на шкалу `SELENA-SLEDAI`
- `FRAX` (остеопороз): интерпретация риска меняется с ростом результата FRAX%, граничные
  значения возраста пациента (40 и 90 лет)
- Навигация из раздела «Ревматология» обратно в «Вакцинацию»

### `VaccinationApiTest` — API калькулятора вакцинации (REST Assured, без браузера)
Бьёт напрямую в `POST /api/submit` — реальный бэкенд-эндпоинт (сервер генерирует PDF
через ReportLab; `blob:`-ссылка, которую создаёт браузер, — это уже скачанный ответ,
а не клиентская генерация). Маппинг полей формы на поля API и их поведение
установлены эмпирически (прямыми запросами из консоли браузера) перед написанием тестов:
- Успешная генерация PDF: с минимальным набором полей, со всеми полями пациента,
  с данными законного представителя.
- `422` при отсутствии `visit_date` или `start_vaccinate_date` — единственных полей,
  чьё отсутствие (не пустое значение, а именно отсутствие) ломает генерацию.
- Сервер не валидирует формат `visit_date` — некорректная строка всё равно даёт
  `200` и PDF (задокументированное текущее поведение, не «правильное»).
- `405` на `GET`/`DELETE` — поддерживается только `POST`.

**Запуск с видимым браузером:**
```bash
mvn clean test -Dheadless=false
```

Запуск в headless-режиме (по умолчанию):
```bash
mvn clean test
```
##🤖 Telegram-бот

Бот работает в режиме polling с параллельным Flask-сервером для health check.

Команды:

    /start — приветствие.

    /run — показать меню выбора раздела сайта (🌐 Все разделы / 💉 Вакцинация /
    🦴 Ревматология / 🔌 API вакцинации), затем меню выбора браузера
    (🌐 Chrome + Firefox / 🖥 Только Chrome / 🦊 Только Firefox) и запустить
    тесты. Выбор передаётся в workflow_dispatch inputs `test_class` (имя
    JUnit-класса или `all`) и `browser` (`chrome`/`firefox`/`all`) —
    run-tests.yml подставляет `test_class` в `mvn test -Dtest=...`, а `browser`
    определяет матрицу job'ов (один браузер вместо обоих).

### 🧪 Тесты самого бота

Логика `bot.py` (выбор раздела, запрос к GitHub Actions API, обработка ошибок)
покрыта юнит-тестами `bot/test_bot.py` (pytest, Telegram/GitHub API замоканы).
Запускаются автоматически в `.github/workflows/test-bot.yml` при изменениях
в `bot/**`, локально:

```bash
pip install -r bot/requirements.txt -r bot/requirements-test.txt
pytest bot/test_bot.py -v
```

Что приходит:

    Статус запуска (🔄)

    Ожидание завершения (⏳)

    Скриншот Allure-отчёта для каждого браузера + ссылка на полный отчёт.

    Финальное сообщение «✅ Все тесты завершены!» со ссылкой на отчёт.

▶️ Запуск

Локально:
```bash

mvn clean test
mvn allure:serve
```

Локально с Docker (Selenium Grid):
```bash

docker compose up -d
mvn clean test -Dbrowser=chrome -Dgrid.url=http://localhost:4444/wd/hub
mvn allure:serve
```

Через бота:

    **Прогресс-бар:** при выполнении `/run` бот показывает динамическую шкалу выполнения, которая обновляется в реальном времени. Это даёт пользователю обратную связь о ходе выполнения тестов.
    Открой скриншот или ссылку на отчёт.
    Дождись сообщения о завершении.
